De Código a Probabilidad

Entendiendo el cambio de paradigma en Ingeniería de Software

Tradicional
⚙️

Software Determinista

En el software tradicional, escribimos reglas explícitas. Si `A` entonces `B`. Para la misma entrada, el sistema siempre produce exactamente la misma salida.

  • Reglas creadas por humanos
  • Lógica explícita (if/else)
  • 100% predecible y reproducible
Nuevo Paradigma
🎲

Modelos Probabilísticos (LLMs)

Un LLM no ejecuta reglas; ejecuta probabilidades. No sabe qué es cierto, solo sabe qué token (palabra) es el más probable que siga al contexto actual.

  • Reglas inferidas de los datos
  • Lógica probabilística (pesos)
  • Salidas variables (incluso con la misma entrada)
Cambio Mental Clave: No estamos llamando a una API tradicional que consulta una base de datos. Estamos interactuando con un motor estadístico que "alucina" texto de forma estructurada.

Entrenamiento vs Inferencia

¿Dónde ocurre la magia y dónde pagamos la factura?

Fase 1
🏋️

Entrenamiento (Training)

Es la fase donde el modelo "aprende". Lee terabytes de texto, encuentra patrones y ajusta sus parámetros matemáticos. Toma meses y cuesta millones de dólares en GPUs.

El Resultado

  • Archivo binario enorme (ej. 140GB).
  • Modelo congelado (no aprende más).
  • Conocimiento limitado a la fecha de corte.
Fase 2 (Producción)
🚀

Inferencia (Inference)

Es el proceso de usar el modelo ya entrenado. Le pasamos un prompt de entrada y realiza millones de cálculos para predecir la siguiente palabra usando parámetros congelados.

Implicaciones

  • Fase que controlas como Ingeniero.
  • Consume memoria de GPU intensamente.
  • Se cobra por "Token", no por request.

El Misterio de los Parámetros

¿Qué significa que un modelo tenga "8B" o "70B" parámetros?

🧠

Los Parámetros

Son los números (pesos) en la red neuronal que determinan cuán fuertemente se conectan los conceptos. Representan el "conocimiento comprimido" del modelo.

  • Modelos Pequeños (8B): Rápidos, baratos, caben en laptop. Ideales para clasificación o RAG.
  • Modelos Grandes (70B+): Lentos, caros. Profundo razonamiento lógico y factual.
Regla de Ingeniería: No uses un modelo de 70B para una tarea que puede hacer uno de 8B. El verdadero talento es orquestar modelos pequeños especializados (routers), reservando los grandes para razonamiento complejo.

Conclusión

De reglas estrictas a orquestación probabilística

✅

Key Insights

  • Los LLMs no son bases de datos; son motores de predicción estadística.
  • El modelo en producción (Inferencia) es inmutable.
  • Para inyectar conocimiento nuevo, usamos Contexto (RAG), no entrenamiento.
