Módulo 01: AI Foundations

De Código a Probabilidad

Entendiendo el cambio de paradigma en Ingeniería de Software

El Software Tradicional vs Modelos de IA

⚙️

Software Determinista

En el software tradicional, escribimos reglas explícitas. Si `A` entonces `B`. Para la misma entrada, el sistema **siempre** produce exactamente la misma salida.

  • Reglas creadas por humanos
  • Lógica explícita (if/else)
  • 100% predecible y reproducible
🎲

Modelos Probabilísticos (LLMs)

Un LLM no ejecuta reglas; ejecuta **probabilidades**. No sabe qué es cierto, solo sabe qué token (palabra) es el más probable que siga al contexto actual.

  • Reglas inferidas de los datos
  • Lógica probabilística (pesos)
  • Salidas variables (incluso con la misma entrada)
Cambio Mental Clave: No estamos llamando a una API tradicional que consulta una base de datos. Estamos interactuando con un motor estadístico que "alucina" texto de forma estructurada.

Entrenamiento vs Inferencia

¿Dónde ocurre la magia y dónde pagamos la factura?

🏋️

1. Entrenamiento (Training)

Es la fase donde el modelo "aprende". Lee terabytes de texto, encuentra patrones y ajusta sus **parámetros** (pesos matemáticos). Es un proceso que toma meses y cuesta millones de dólares en GPUs.

El resultado:

  • Un archivo binario enorme (ej. 140GB para un modelo de 70B parámetros).
  • El modelo queda "congelado". No aprende nada nuevo por sí solo una vez termina.
  • Sabe "cómo" hablar, pero su conocimiento factual llega hasta la fecha de corte.
🚀

2. Inferencia (Inference)

Es el proceso de **usar** el modelo ya entrenado. Le pasamos un texto de entrada (prompt) y realiza millones de multiplicaciones matriciales usando sus parámetros congelados para calcular la siguiente palabra.

Implicaciones en Producción:

  • Es la fase que controlas como Ingeniero (vía API o local).
  • Consume VRAM (memoria de GPU).
  • Se cobra/mide por "Token", no por llamada.

El Misterio de los Parámetros

¿Qué significa que un modelo tenga "8B" o "70B" parámetros?

🧠

Los Parámetros

Son los números (pesos) en la red neuronal que determinan cuán fuertemente se conectan los conceptos. Representan el "conocimiento comprimido" del modelo.

  • Modelos Pequeños (8B): Rápidos, baratos, caben en una laptop. Ideales para tareas específicas (resumir, clasificar).
  • Modelos Grandes (70B+): Lentos, caros, requieren clusters. Tienen profundo razonamiento y conocimiento factual.

La regla de oro del Ingeniero de IA:

No uses un modelo de 70B parámetros para una tarea que puede hacer uno de 8B. El verdadero talento en arquitectura IA es orquestar modelos pequeños especializados (routers) reservando los modelos gigantes solo para tareas de razonamiento profundo.

Conclusión

De reglas estrictas a orquestación probabilística

✅

Lo que debes llevarte de esta lección:

  • Los LLMs no son bases de datos; son motores de predicción estadística.
  • El modelo en producción (Inferencia) es inmutable; no "aprende" de tus preguntas a menos que se re-entrene.
  • Para inyectar conocimiento nuevo, usamos Contexto (RAG), no entrenamiento.
