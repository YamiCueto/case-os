Security Boundary

Nunca subas código propietario, credenciales, secretos, PII o información confidencial a una herramienta de IA no autorizada por tu organización. CASE Academy no requiere ni almacena tu código. Este laboratorio es un playbook técnico que ejecutas localmente en tu propio entorno y repositorio con tus herramientas autorizadas.

01 —

Context: La fragilidad del lenguaje natural

Los modelos de lenguaje no ejecutan código; infieren continuaciones probabilísticas. Cuando pasas una instrucción ambigua a un LLM en un pipeline automatizado, cualquier variación en temperatura, versión de modelo o reformulación del usuario puede destruir tu integración. Para que la IA sea confiable en ingeniería, no escribimos "prompts decorativos": diseñamos contratos de instrucción deterministas y acorralados.

02 —

Selección del Objetivo Real

Desafío de Modernización Corporativa

No trabajaremos con proyectos de juguete. Elige una necesidad real de tu repositorio o proyecto corporativo actual que requiera análisis o transformación automatizada. Por ejemplo:

  • Una rutina, servicio o stored procedure legacy sin documentación ni pruebas unitarias.
  • Un endpoint cuyo payload requiere extracción estructurada de campos de auditoría.
  • Una clase monolítica que requiere identificación de riesgos antes de una migración.
  • Un log extenso de errores que requiere clasificación determinista de severidad y causa raíz.
03 —

Estructura del AI Instruction Contract

Tu contrato de instrucciones debe componerse de los siguientes 6 bloques esenciales:

01 · INTENT & ROLE

Define el rol especializado del modelo y el objetivo exacto sin rodeos ni conversación informal.

02 · CONSTRAINTS (NEGATIVE)

Reglas explícitas de lo que el modelo NUNCA debe hacer (no inventar, no usar markdown, no asumir).

03 · INPUT CONTRACT

Delimitadores claros para separar las instrucciones del contenido/código a analizar.

04 · OUTPUT SCHEMA

Esquema JSON/YAML estricto con especificación de tipos de datos y campos requeridos.

05 · FAILURE CONDITIONS

Comportamiento esperado cuando falte contexto o el input viole precondiciones.

06 · VALIDATION PROTOCOL

Criterios de verificación determinista para automatizar o auditar el resultado.

04 —

Playbook de Ejecución Paso a Paso

PASO 1 Identificar el componente y abstraer sensibles

Selecciona el código o datos de tu proyecto real. Reemplaza IPs, contraseñas, nombres de clientes o datos PII por placeholders tipo [CLIENT_ID], [API_KEY_PLACEHOLDER].

PASO 2 Diseñar la primera versión del AI Instruction Contract

Abre tu IDE o editor. Redacta el contrato usando delimitadores Markdown (ej. <context>, <constraints>, <schema>). Especifica explícitamente que la salida debe ser parseable por código sin intervención manual.

PASO 3 Probar el contrato contra el Primer Caso Real (Caso Base)

Ejecuta el contrato en tu herramienta de IA autorizada (GitHub Copilot, Cursor, Claude, ChatGPT Enterprise). Copia el output y verifica si pasa un JSON.parse() o validador equivalente.

PASO 4 Someter a la prueba de estrés (Segundo Caso o Caso Borde)

Prueba la misma instrucción exactamente igual pero con un código incompleto, con errores de sintaxis o con campos faltantes. ¿El modelo respetó las Failure Conditions o inventó datos? Refina los Constraints.

Criterios de Aceptación del Laboratorio

Este laboratorio se considera Completado cuando hayas documentado en tu entorno personal/corporativo:

  1. El AI Instruction Contract completo redactado para tu necesidad real.
  2. El resultado del análisis anonimizado sobre el primer caso de prueba.

  4. La lista de iteraciones realizadas entre la versión v1 (ambigua) y la versión final (determinista).
