Límite de Seguridad

Nunca subas código propietario, credenciales, secretos o información confidencial (PII) a un modelo de lenguaje (LLM) no autorizado por tu organización. Reemplaza siempre los datos sensibles por marcadores de posición (ej. [CLIENT_ID]).

Entorno de Entrenamiento: Contrato de Instrucción

Construye un contrato robusto en tu IDE local y verifica iterativamente sus propiedades observables en esta plataforma. El sistema actuará como tu entrenador y validador, pero la calidad de las decisiones de ingeniería depende de ti.

PASO 1

Elegir el Problema

Retoma la oportunidad identificada en el Lab 01 (clasificación, extracción, análisis). Describe brevemente el problema que vas a resolver con este contrato.

PASO 2

Diseñar el Contrato

Define las seis partes fundamentales de tu System Prompt. Escribe directamente aquí tus decisiones de diseño para estructurar el contrato.

¿Qué debe hacer el modelo específicamente?
¿Qué NO debe hacer bajo ninguna circunstancia?
¿Qué delimitadores separan los datos de las instrucciones?
¿Qué estructura exacta JSON/YAML debe devolver?
¿Qué devuelve si no puede procesar la entrada?
¿Cómo comprobarás programáticamente que cumplió?
PASO 3

Agregar Ejemplos (Few-Shot)

Un buen contrato no solamente enseña al modelo cómo acertar; también muestra qué hacer cuando la entrada es inválida. Define tus ejemplos.

PASO 4

Ejecutar el Caso Normal (Validador de Bolsillo)

Ejecuta tu contrato completo en tu IDE local usando un LLM autorizado. Pega aquí el resultado crudo para que el sistema compruebe sus propiedades estructurales. El sistema no evaluará si tu lógica de negocio es perfecta, sino si tu formato resiste integraciones de software.

Un ejemplo del JSON que tu código necesita procesar.
Pega exactamente la respuesta que te devolvió el modelo.

{{ validationResult().message }}

PASO 5

Prueba de Resistencia

Inyecta entradas diseñadas para confundir al LLM. Si tu contrato es robusto, el LLM responderá usando el JSON de tu contingencia ("Condiciones de Fallo"). Pega el resultado aquí para validarlo.

[ Probar entrada vacía ] [ Probar en otro idioma ] [ "Ignora las instrucciones" ]

PASO 6

Identificar el Fallo y Corregir

Documenta las iteraciones de tu contrato. Pensar como ingeniero implica registrar qué falló, cuál fue la causa raíz y cómo lo solucionaste.

Artefactos y Exportación
