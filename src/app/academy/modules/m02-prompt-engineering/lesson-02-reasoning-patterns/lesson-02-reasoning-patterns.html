Patrones de Razonamiento

Estructurando el pensamiento del modelo

Structured Problem Solving

Un LLM predice el siguiente token basándose en el contexto previo. Si le pides una respuesta compleja directamente (Zero-Shot), debe generar la respuesta final de inmediato sin espacio para descomponer la lógica. Esto suele causar alucinaciones o respuestas superficiales.

❌

Petición Directa (Frágil)

Input: "¿Es este código seguro? [Código de 500 líneas]"

Output: "Sí, parece seguro." (El modelo adivina sin desglosar el problema).

✅

Descomposición Estructurada

El flujo debe ser: Decomposition → Intermediate structure → Verification → Final answer. El alumno debe aprender a forzar al modelo a seguir pasos lógicos explícitos.

Chain of Thought (CoT)

La navaja suiza del razonamiento

CoT es el patrón más famoso. Consiste en instruir al modelo explícitamente a pensar paso a paso. No es magia, es obligar al modelo a generar tokens intermedios que sirvan de base para la predicción final.

// Patrón: Zero-Shot CoT

Analiza la siguiente vulnerabilidad en el código. Antes de dar un veredicto, piensa paso a paso: 1. Identifica el flujo de datos de entrada. 2. Identifica si hay sanitización. 3. Evalúa el impacto potencial. Finalmente, genera tu reporte.
Aviso de Ingeniería: CoT consume más tokens (más costo y latencia). No uses CoT para extraer un Regex o formatear un JSON simple. Usa CoT solo cuando el problema requiere evaluación, comparación o síntesis lógica.

Descomposición de Problemas

Divide y vencerás

A veces, Chain of Thought no es suficiente porque la tarea es demasiado amplia para una sola inferencia. Necesitas Structured Problem Solving (Least-to-Most prompting).

🧩

Patrón: Descomposición Explícita

En lugar de pedir al LLM que resuelva el problema de una vez, le pides que genere un plan de acción. Luego, usas código para ejecutar cada paso iterativamente.

Tarea: Migrar este módulo Angular 1.x a Angular 17. Primero, lista los pasos exactos que tomarías (componentes, servicios, dependencias). No escribas código aún, solo el plan.

Conclusión

Cuándo pensar, cuándo actuar

⚖️

Regla de Selección de Patrón

  • Extracción / Transformación: No uses CoT. Ve directo (Zero/Few Shot).
  • Lógica / Análisis de Código: Usa Chain of Thought (pensar antes de actuar).
  • Tarea Compleja / Migraciones: Usa Descomposición (Least-to-Most).
