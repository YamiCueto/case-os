● Módulo 02: Ingeniería de Prompts

Comportamiento Confiable

Ingeniería para el control, no magia para el determinismo

El mito del "Prompt Perfecto"

❌

Determinismo Absoluto

Pensar que si encuentras las "palabras mágicas", el LLM se convertirá en una función matemática determinista. Falso. Es un motor estadístico; siempre habrá varianza.

✅

Comportamiento Reproducible

Aceptar la variabilidad y diseñar restricciones (constraints) que acorralen al modelo para que cualquier variación semántica caiga dentro de tu caso de uso aceptable.

Regla de Ingeniería: El Prompt Engineering no busca eliminar la probabilidad, busca reducir su desviación estándar. Queremos resultados confiables, restringidos y reproducibles.

Zero-Shot vs Few-Shot

Mostrando en lugar de explicando

Básico

Zero-Shot Prompting

Pedirle algo al modelo sin ejemplos. Funciona bien para tareas universales, pero fracasa cuando necesitas formatos estrictos.

Ejemplo Frágil:

Extrae las entidades de este texto y devuélvelas en formato JSON.

El LLM puede responder: "¡Claro! Aquí tienes: {{ '{' }}...{{ '}' }}" rompiendo tu parser.

Avanzado

Few-Shot Prompting

Dar ejemplos del comportamiento deseado dentro del prompt. Alinea los pesos del modelo hacia tu tarea.

Ejemplo Robusto:

Input: "Compré manzanas" Output: ["manzanas"] Input: "Se cayó el servidor AWS" Output:

Al ver el patrón, el modelo completará `["servidor AWS"]` sin charla.

Negative Constraints

Lo que NO debe hacer es tan importante como lo que SÍ

🛡️

Protegiendo los bordes

Los LLMs sufren de complacencia (sycophancy). Tienden a querer justificar sus respuestas. Para un flujo automatizado, necesitamos cortar eso.

NO USAR: "Intenta no incluir texto antes del JSON." (El modelo lee "incluir texto" y lo toma como sugerencia).
SÍ USAR: "WARNING: Return ONLY valid JSON. Do not include markdown formatting. Any text outside the JSON structure will cause a system crash."
Concepto de Ingeniería: Las "negative constraints" (como NO EXPLANATION) no garantizan que el modelo cumpla el contrato. Solo reducen la probabilidad de desviación. La garantía se logra mediante validación externa en tu código.

Conclusión

Hacia un comportamiento de sistema

🎯

Resumen de la Ingeniería

  • Abandona la ilusión de convertir un modelo probabilístico en una función matemática pura.
  • Reduce la desviación estándar mediante reglas explícitas (System Prompt) y ejemplos (Few-Shot).
  • Usa restricciones negativas estrictas ("Return ONLY...") para proteger tu código.
