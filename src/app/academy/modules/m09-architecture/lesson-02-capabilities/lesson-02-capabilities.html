Least Autonomy Necessary

Recuperando el Principio de M05

⚖️

Úsalo solo si lo necesitas

Como vimos en el Módulo 05, la autonomía introduce imprevisibilidad y riesgo.

  • Si el flujo es determinista, no uses un Agente.
  • Si los datos cambian poco, usa caché, no RAG dinámico.
  • Si integras un solo sistema estático, no necesitas MCP.

Construyendo el Puzzle

Componentes Independientes

Cuando un requerimiento exige una capacidad, esta debe diseñarse como un componente aislado, protegido por fronteras (Boundaries):

Memoria (Context)

Bases vectoriales o APIs de búsqueda. Debe exponer una interfaz estándar (ej. search()) independiente de si usas Pinecone o PostgreSQL.

Acción (Tools)

Herramientas locales o Servidores MCP. Protegidas por un Tool Boundary que exige validación (HitL) antes de mutar el estado externo.

Evaluación (Security)

El Pipeline de CI/CD para prompts y respuestas. Funciona como un middleware de entrada/salida que enmascara PII y frena alucinaciones.
