The Agent Loop

Action → Observation → State

El Corazón del Agente

Un agente no es un LLM súper-inteligente. Un agente es simplemente un modelo metido dentro de un bucle (Loop) en tu código. Este bucle operacional se conoce frecuentemente por el patrón ReAct (Reason + Act), pero lo crucial no es el "Thought" interno, sino la capacidad de actuar y observar las consecuencias.

🔄

El Bucle Operacional

El código le da un objetivo al LLM. El LLM propone una Acción. El código la ejecuta y le devuelve la Observación. Con esta nueva información, el LLM propone la siguiente acción, hasta que decide que tiene suficiente información para dar la Respuesta Final.

El Ciclo en Acción

Resolviendo problemas complejos

User Request: "¿Qué clima hace hoy en Madrid? Mándale el reporte a Juan."

LLM Action: call getWeather(city="Madrid")
Code Observation: "24 grados, parcialmente nublado"
LLM Action: call searchKnowledge(query="email de Juan")
Code Observation: "juan@empresa.com"
LLM Action: call sendEmail(to="juan@empresa.com", body="En Madrid hace...")
Code Observation: "Success: Email sent"
LLM Action: Return Final Answer

Guardrails Operacionales

Previniendo el desastre

Los Agent Loops son potentes, pero si una herramienta falla o el LLM se confunde, pueden entrar en un loop infinito (ej. intentar llamar a `search()` repetidamente con el mismo error).

🛑

Max Iterations

El código DEBE forzar un límite duro (ej. `max_steps = 10`). Si el agente no ha terminado en 10 ciclos, se aborta y se devuelve un error al usuario.

💸

Cost Control

Cada iteración del loop consume tokens. Se debe monitorear el crecimiento acumulativo del contexto y su impacto en latencia y costos.
