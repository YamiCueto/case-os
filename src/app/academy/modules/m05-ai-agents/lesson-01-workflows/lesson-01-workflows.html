Least Autonomy Necessary

No todo problema necesita un agente

La Escalera de la Autonomía

En ingeniería de software con IA, la autonomía no es un objetivo, es un costo. Mientras más autonomía otorgas a un modelo, menor es tu control sobre la ejecución, la latencia y los costos económicos.

Regla Arquitectónica: Construye utilizando siempre el nivel más bajo de autonomía que resuelva tu caso de uso.

1. Deterministic Workflow

Cero autonomía, control absoluto

⚙️

Pipeline Estático

El código dicta la secuencia. El LLM es solo una función dentro del pipeline.

User -> Code -> LLM -> Code

Características

  • Predictibilidad: Máxima (100%).
  • Costo y Latencia: Mínima (1 sola llamada al LLM).
  • Uso: Clasificación, Extracción RAG, Traducción, Resúmenes.

2. Tools vs 3. Agent Loop

Otorgando capacidad de decisión

🛠️

Tool-Using Workflow

El LLM recibe una petición y una lista de herramientas. Decide qué herramienta usar y propone los parámetros, pero NO orquesta el ciclo. El código ejecuta la herramienta y termina.

Útil para: Interfaces de búsqueda, ejecución de un solo comando (ej. "Apaga las luces").

🔄

Agent Loop (ReAct)

El LLM decide usar una herramienta, el sistema la ejecuta y devuelve el resultado al LLM para que decida el siguiente paso, repitiendo hasta llegar a un objetivo.

Útil para: Tareas donde los pasos dependen del resultado anterior (Research, Debugging).

4. Autonomous Agent

El extremo de la escalera

⚠️

La caja negra total

Un agente verdaderamente autónomo recibe un objetivo general ("Maximiza las ventas") y decide por sí mismo qué workflows iniciar, qué herramientas descubrir y cuándo detenerse, a menudo ejecutándose en background por horas.

Son impredecibles y difíciles de evaluar. La mayoría de los sistemas empresariales se benefician de mantener la autonomía acotada y utilizar workflows deterministas siempre que sea suficiente.
