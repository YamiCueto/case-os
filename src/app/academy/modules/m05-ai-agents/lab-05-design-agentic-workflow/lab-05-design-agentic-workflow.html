02 —

El "Autonomy Test": Use the least autonomy necessary

Los agentes son caros, lentos y propensos a errores. Antes de diseñar uno, justifica por qué las alternativas más simples fallarían para el problema legacy seleccionado:

¿Los pasos son conocidos de antemano de inicio a fin?
→ SÍ: Fixed Pipeline (Script). Fin del diseño. → NO: Pasar a la siguiente pregunta.
¿Hay estados y transiciones claramente definidos, aunque condicionales?
→ SÍ: State Machine (DAG). Fin del diseño. → NO: Pasar a la siguiente pregunta.
¿La tarea requiere exploración, decisiones dinámicas y re-evaluación constante de resultados fallidos?
→ SÍ: Autonomous Agent justificado. Puedes continuar con el Lab.

04 —

El Artefacto: Agent Specification Document

AGENT SPECIFICATION TEMPLATE CASE OS STANDARD
1. Core Instruction (System Prompt): Definición estricta del rol, el objetivo y las restricciones de razonamiento.
2. Tool Contracts: Firmas JSON/OpenAPI de cada herramienta (nombre, descripción detallada, argumentos requeridos).
3. Guardrails & Limits: Límite máximo de iteraciones (ej. max_steps=5), bloqueo de argumentos prohibidos.
4. Human-in-the-Loop (HITL) - Análisis de Riesgo:
  • READ Actions: Automáticas.
  • WRITE Actions: Auditoría diferida o control condicional.
  • DELETE / FINANCIAL / PRODUCTION Actions: Requieren autorización explícita del humano.
5. Failure & Recovery: ¿Qué ocurre si la herramienta falla? (Timeout, Retry, Fallback al usuario, Abortar el bucle).
6. State Management: ¿Qué información debe retener el agente entre iteraciones?
