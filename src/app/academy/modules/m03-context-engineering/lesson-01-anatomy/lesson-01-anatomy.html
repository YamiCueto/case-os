Anatomy of Context

El modelo no ve tu aplicación. Solo ve lo que tú decides enviarle.

La ilusión de omnisciencia

Como humanos, al interactuar con una interfaz asumimos que el modelo "sabe" qué página estamos viendo, qué usuario somos o qué datos acabamos de guardar. Esto es falso. Un LLM en producción es una API stateless (sin memoria). Cada inferencia arranca desde cero.

Paradigma Base: Context Engineering no es "escribir párrafos largos en el prompt". Es el proceso arquitectónico de capturar el estado dinámico de tu aplicación y transformarlo en texto estructurado antes de tocar la API del LLM.
● Módulo 03: Context Engineering

Las Seis Fuentes de Verdad

El origen de la información

1. Static Context

Reglas de negocio fijas, directivas del sistema (System Prompts). No cambian entre peticiones.

2. User Context

Perfil, permisos, preferencias o ubicación del usuario ejecutando la acción.

3. Application State

Datos de la pantalla actual: "El usuario está viendo la factura #1024".

4. Retrieved Context

Conocimiento dinámico inyectado desde bases vectoriales (RAG) o búsquedas tradicionales.

5. Tool Context

Resultados de funciones que el modelo acaba de ejecutar en el background.

6. Conversation Context

El historial de mensajes previos. (Que a menudo es el que más basura acumula).

Disponible vs. Útil

El síndrome de Diógenes en el Prompt

El error de ingeniería más común es concatenar las seis fuentes de contexto sin discriminar y enviarlas al LLM.

🚨

Contexto Disponible

Toda la información a la que tu backend tiene acceso (El perfil completo de BD del usuario, los 50 mensajes previos, todo el contenido de la página actual).

🎯

Contexto Útil

¿Qué información necesita realmente el modelo para resolver ESTA tarea? Si la tarea es resumir un ticket, no necesitas su historial de compras de hace 2 años.

La Pregunta Fundamental

Antes de pasar a la siguiente lección, recuerda esto:

"Si le dieras esta misma información (y nada más) a un colega humano recién contratado... ¿podría resolver el problema?"

Si la respuesta es no, te falta contexto útil. Si la respuesta es "se confundiría con tanta información", tienes demasiada basura disponible.
