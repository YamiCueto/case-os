01 —

El Principio del Minimum Useful Context

Existe un mito común en IA: "cuanto menos contexto pases, mejor". Esto es falso. El principio real de ingeniería es Minimum Useful Context: proveer todo lo que el modelo necesita para razonar sobre el problema, pero ni un solo archivo irrelevante o redundante que diluya su ventana de atención.

La Trampa del Ruido en Sistemas Legacy: En repositorios reales corporativos, el problema rara vez es la falta de información. Es la sobreabundancia de archivos desactualizados, configuraciones duplicadas y dependencias cruzadas. Pasar el proyecto entero al LLM destruye la precisión y agota la ventana de atención.

02 —

Selección de la Tarea Real de Modernización

Desafío Multi-Archivo en Repositorio Real

Elige una tarea de tu codebase corporativo cuyo análisis o refactorización involucre múltiples componentes interconectados. Por ejemplo:

  • Migrar un servicio que depende de 1 controlador, 2 servicios auxiliares, 1 DTO y 1 script SQL.
  • Extraer lógica de negocio incrustada en un componente UI monolítico con estado global.
  • Auditar el flujo de autorización de un endpoint cuya seguridad se valida en middleware + annotation + base de datos.
03 —

El Artefacto Entregable: Context Manifest

Descargar Plantilla (MD)

Antes de interactuar con el asistente de IA, debes formalizar el razonamiento del contexto en un Context Manifest. Descarga la plantilla oficial y documenta tu contexto de forma estructurada.

CONTEXT MANIFEST SPEC v1.0 TEMPLATE OFICIAL
1. [ TASK ]

¿Qué problema real vamos a resolver? Objetivo y alcance.

2. [ REQUIRED CONTEXT ]
¿Qué información necesita el agente? Aplica los filtros de Relevance, Recency y Redundancy para cada artefacto.
3. [ EXCLUDED CONTEXT ]
¿Qué información decidimos NO incluir? Justifica para evitar ruido.
4. [ DEPENDENCIES ]

¿Qué relaciones (componentes, APIs, tablas) debemos preservar?

5. [ ASSEMBLY ]

¿Cómo vamos a organizar el contexto seleccionado (tags XML, estructura)?

6. [ CONTEXT HYPOTHESIS ]

¿Qué debería poder hacer el agente con este contexto?

7. [ VALIDATION ]

¿Cómo comprobaremos técnica o lógicamente que el contexto fue suficiente?

8. [ CONTEXT GAPS ]

¿Qué información faltó luego de ejecutar? Documenta la brecha.

04 —

Playbook de Ejecución Paso a Paso

PASO 1 Definir el Problema y Descargar el Manifiesto

Descarga la plantilla del manifiesto y describe detalladamente la tarea o problema real a resolver (Sección 1).

PASO 2 Completar el Context Manifest v1.0

Analiza los archivos locales y documenta sistemáticamente qué archivos se requieren y cuáles se excluyen, justificando cada decisión (Secciones 2-7).

PASO 3 Ensamblar y Ejecutar el Payload

Organiza la información como lo definiste en Assembly (Sección 5) y envíasela a tu Asistente Autorizado de IA (sin incluir código propietario no permitido).

PASO 4 Auditar y Registrar Context Gaps

Evalúa si el modelo logró cumplir la hipótesis. Si falló porque le faltó algún archivo o tabla, documenta esa brecha en la Sección 8 del manifiesto para tu próxima iteración.

Herramientas Autorizadas

El Puente Pedagógico hacia M04 (Retrieval / RAG)

La pregunta inevitable de ingeniería

Hasta este laboratorio, tú como ingeniero seleccionaste manualmente los archivos e inspeccionaste las dependencias una por una.

¿Qué ocurre cuando el sistema corporativo no tiene 10 archivos, sino 50.000 documentos, tablas y repositorios distribuidos?

En Module 04 (Retrieval & RAG) aprenderemos a automatizar esta selección manual mediante vectores, búsquedas híbridas y ranking semántico.
