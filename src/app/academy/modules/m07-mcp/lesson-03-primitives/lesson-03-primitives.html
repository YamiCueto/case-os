Las Primitivas del Protocolo

Resources, Tools y Prompts

El Lenguaje de la Interoperabilidad

Cuando un Client se conecta a un Server, el servidor le envía un manifiesto (JSON) con lo que puede ofrecer. Esta oferta se agrupa estrictamente en tres categorías fundamentales.

Regla de Oro: Confundir un Resource con una Tool es el error más común al diseñar servidores MCP. Comprender esta diferencia es crucial para escalar el ecosistema.
● Módulo 07: MCP

1. Resources

Datos controlados por el Servidor

📄

"Acceder a Información"

Un Resource representa datos o contexto que el servidor expone (ej. un archivo local, un ticket de base de datos, un log). Se identifican mediante URIs, similares a `file:///...` o `postgres://...`.

  • El usuario o el Host suelen inyectarlos al contexto antes o durante la generación.
  • Son operaciones seguras, de solo lectura (Read-Only).
  • El agente no está "ejecutando" nada; simplemente está "leyendo" un documento proveído por el Servidor.
● Módulo 07: MCP

2. Tools

Acciones controladas por el Modelo

🛠️

"Pedir que ocurra una operación"

Una Tool es una función ejecutable (mutación o búsqueda compleja). El Servidor expone el JSON Schema de la herramienta, y el LLM decide cuándo y con qué parámetros llamarla (como vimos en M05).

  • El modelo (agente) es quien invoca activamente la herramienta durante su loop.
  • Pueden tener efectos secundarios (ej. `github_create_pr`, `execute_sql_query`).
  • Debido a que el modelo las controla, requieren validación, permisos y en muchos casos, aprobación humana (HitL).

3. Prompts & Práctica

El Universal Connector

✨

Prompts (Templates)

La tercera primitiva son plantillas reutilizables predefinidas por el Servidor. Facilitan al usuario interactuar de manera estandarizada con un dominio (ej. un prompt de "Analizar este ticket de Jira" que automáticamente vincula los Resources correctos).
