LAB 07 · REAL ENGINEERING Module 07 · MCP · ⏱️ 90 min · Advanced · Design Specification

Para este Lab, trabajarás sobre una base MySQL local de la CFA (o una integración equivalente en tu entorno). Tu objetivo no es programar la conexión real a la plataforma, sino diseñar la MCP Integration Specification: un contrato arquitectónico que determina cómo exponer esas capacidades a un Agente de IA manteniendo la seguridad y limitando la superficie de ataque.

01 —

Understand the Existing Integration

Antes de diseñar MCP, documenta qué existe actualmente. Identifica las tablas involucradas, datos sensibles, operaciones de escritura/lectura y los efectos secundarios de interactuar con el sistema legacy.

02 —

Tool or Resource?

Clasifica cada capacidad deseada en una de las dos primitivas principales de MCP.

RESOURCE (Read-Only)
  • mysql://localhost/cfa/schema
  • Información contextual que el agente puede leer para entender el entorno.
TOOL (Executable)
  • search_orders(customer_id)
  • Operaciones que reciben argumentos y ejecutan lógicas de negocio o side-effects.
03 —

The Contract & Least Privilege

Diseña el esquema formal (Name, Inputs, Outputs). No expongas métodos genéricos y peligrosos. Reduce la superficie utilizando una matriz de decisión:

Capacidad Decisión Justificación
Consultar cliente EXPOSE Read-only y acotado
Ejecutar SQL arbitrario DO NOT EXPOSE Superficie excesiva / Inyección
Actualizar estado orden RESTRICT (HITL) Side-effect (Requiere validación)
04 —

Security, HITL & Audit

Establece explícitamente cuándo una acción es `AUTO`, `AUDIT` o `HUMAN APPROVAL`. Todo contrato debe incluir trazabilidad: ¿Quién la llama? ¿Cuándo? ¿Con qué parámetros?

05 —

Failure & Recovery

¿Qué ocurre si MySQL falla? ¿Cómo debe reaccionar el Agente? En el contrato debes anticipar fallos como DATABASE_UNAVAILABLE para que el LLM no invente resultados, no haga retries infinitos y escale el error al usuario humano.

07 —

MCP Integration Review

Después de diseñar el contrato, realiza una revisión final respondiendo este checklist:

  • CAPABILITY: ¿Realmente necesita el agente esta capacidad?
  • PRIVILEGE: ¿Puede reducirse la superficie?
  • INPUT: ¿Los parámetros están suficientemente restringidos?
  • OUTPUT: ¿El resultado es verificable?
  • SIDE EFFECT: ¿Produce cambios en el sistema?
  • AUTHORIZATION: ¿Quién puede aprobarlo?
  • AUDIT: ¿Podemos reconstruir qué ocurrió?
  • FAILURE: ¿Qué pasa cuando falla?
  • REVERSIBILITY: ¿Podemos deshacer el efecto?
[ APPROVE ] [ REVISE ] [ REJECT ]
