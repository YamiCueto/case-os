Arquitectura de MCP

Host, Client y Server

La Topología Oficial

MCP se basa en una topología estricta. Es vital entender la diferencia entre quién pide información y quién la provee. Nunca debes confundir al Host con el Client.

Host
 ├── MCP Client
 │      │
 │      │ MCP (Transport)
 │      ↓
 │   MCP Server
 │      ├── Tools
 │      ├── Resources
 │      └── Prompts
● Módulo 07: MCP

Las Tres Capas

Desglosando la arquitectura

Host

Es la aplicación principal donde el usuario interactúa (ej. Claude Desktop, Cursor IDE). Un Host puede instanciar múltiples Clientes MCP para conectarse a diferentes servidores simultáneamente.

MCP Client

Es el módulo dentro del Host que mantiene la conexión 1 a 1 con un Servidor MCP mediante el protocolo estándar. Negocia la conexión y transfiere peticiones.

MCP Server

Es el programa externo (ligero y sin estado) que expone el acceso a los sistemas locales o remotos (ej. PostgreSQL, Jira). Responde a las peticiones del Cliente mostrando qué capacidades tiene (Tools, Resources).

Transportes Modernos

Especificación 2026-07-28

¿Cómo se comunican el Cliente y el Servidor físicamente? La especificación actual define dos transportes principales estandarizados (notar que HTTP+SSE es considerado legacy/deprecado):

💻

STDIO

Usado para integraciones locales. El Host inicia el proceso del Servidor (ej. `npx mi-servidor-mcp`) y se comunican enviando JSON-RPC a través de los streams estándar (Standard Input / Standard Output).

🌐

Streamable HTTP

Usado para integraciones remotas corporativas o en la nube. Permite flujos bidireccionales eficientes sin las limitaciones históricas de SSE, adaptándose mejor a firewalls empresariales.

Stateless & Capabilities

Principios de diseño

🧩

El núcleo Stateless y el Descubrimiento

Un cambio clave en las especificaciones recientes es el núcleo stateless de MCP. Los servidores no recuerdan el estado de la conversación. En su lugar, cuando el Cliente se conecta, el Servidor declara explícitamente sus Capabilities (qué puede hacer).

Estas Capabilities se dividen en tres primitivas fundamentales. Descubrirlas dinámicamente es la magia que elimina la necesidad de escribir código de integración manual.
