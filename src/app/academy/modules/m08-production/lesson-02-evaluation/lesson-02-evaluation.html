Jerarquía de Evaluación

De lo exacto a lo semántico

No todo es LLM-as-a-Judge

Un error común en Producción es utilizar un LLM para evaluar todo. Esto es lento, costoso y propenso a errores (un LLM evaluando mal a otro LLM). La evaluación debe estructurarse como un embudo, desde comprobaciones baratas y exactas hasta revisiones humanas costosas.

● Módulo 08: IA en Producción

El Embudo de Evaluación

Las capas de defensa

1. Deterministic Checks (Code/Regex)

Verificaciones exactas. ¿La respuesta contiene un JSON válido? ¿Mide menos de 500 caracteres? Costo: $0.

2. Structured / Rule-based Evaluation

¿Contiene una palabra prohibida? ¿El esquema coincide con el modelo de la Base de Datos? Costo: Casi nulo.

3. Semantic Evaluation (Embeddings)

¿El significado de la respuesta es similar (+90% Cosine Similarity) a una respuesta esperada? Costo: Bajo.

4. LLM-as-a-Judge

Usar un LLM fuerte (ej. GPT-4) para evaluar criterios abstractos de un modelo rápido (ej. GPT-4o-mini). "¿El tono es amable?". Costo: Alto.

5. Human Evaluation

Revisión manual de casos límite o auditorías aleatorias. Costo: Extremadamente alto. No escala.

Golden Datasets & Regression

El equivalente a Unit Tests

¿Qué pasa si cambias tu System Prompt para corregir un bug, o si tu proveedor actualiza el modelo subyacente? ¿Cómo sabes que no rompiste otra funcionalidad?

🏆

Golden Dataset (Conjunto de Datos Dorado)

Un conjunto cerrado de 10 a 100 casos de prueba reales (User Input) junto con su comportamiento esperado (Expected Behavior). Cada vez que modificas el prompt o cambias de modelo, corres el dataset completo por tu Jerarquía de Evaluación para detectar regresiones.

⚠️

Cuando el Juez se equivoca

Especialmente al usar LLM-as-a-Judge, tu rúbrica de evaluación puede estar mal diseñada. Esto produce:

  • False Positive (False Pass): El evaluador aprueba una respuesta que en realidad es mala o maliciosa. Un bug llega a producción.
  • False Negative (False Fail): El evaluador rechaza una respuesta perfectamente válida por ser demasiado estricto. Pérdida de eficiencia.
