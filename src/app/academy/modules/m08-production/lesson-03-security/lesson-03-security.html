Security & Boundaries

El modelo no es un firewall

La falsa sensación de seguridad

Es común creer que si le decimos al modelo "No ejecutes comandos destructivos" en el System Prompt, estamos seguros. Esto es falso. El LLM NO ES una frontera de seguridad. Es probabilístico y susceptible al Prompt Injection (ataques que engañan al modelo para ignorar sus instrucciones).

El Diseño de Fronteras

Aislando al Agente

La seguridad en aplicaciones GenAI se basa en asumir que el modelo será vulnerado, y por tanto, debemos proteger sus "periferias".

Untrusted Input
      ↓
Context Boundary (¿El prompt inyecta PII? Lo enmascaramos)
      ↓
    Model (No confíes en él como firewall)
      ↓
Tool Boundary (Validación, Sandboxing, Human-in-the-Loop)
      ↓
  MCP Server
      ↓
Real System

¿Qué pasa si el modelo recibe una instrucción maliciosa y tiene una herramienta con permisos reales de escritura (Mutation Risk)? Si la Tool Boundary no exige Human Approval, tu base de datos será borrada.

Restricciones Operativas

Ingeniería Multidimensional

Además de la Calidad (Evaluation) y la Seguridad (Boundaries), el ingeniero de IA debe equilibrar constantemente tres restricciones más en Producción:

Latency (Latencia)

Usar GPT-4 para cada micro-tarea produce tiempos de respuesta inaceptables. A veces un modelo más pequeño y tonto pero rápido es mejor si la tarea es sencilla.

Cost (Costo)

El tokenaje escala. Evaluar el costo por predicción es fundamental. Un Golden Dataset enorme corrido por un LLM-as-a-judge pesado te vaciará la billetera.

Reliability (Fiabilidad)

¿Qué pasa si la API de Anthropic/OpenAI cae? Debes diseñar estrategias de Fallback (ej. enrutar temporalmente a un modelo Open Source local).

No existe "la mejor respuesta". Existe "la mejor respuesta dentro de las restricciones del sistema" (Quality + Security + Latency + Cost + Reliability).
