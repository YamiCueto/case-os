Production AI Checklist

Guía de Readiness para Modelos en Producción

Antes de exponer un modelo generativo a usuarios reales o conectarlo a sistemas corporativos, tu equipo debe poder marcar cada uno de estos requisitos arquitectónicos y operativos.

1. Evaluation & Regression

  • [ ] Golden Dataset: Existe un set de 50+ casos de prueba representativos con su comportamiento esperado.
  • [ ] Automated Eval: Se ejecuta una evaluación semántica o LLM-as-a-judge en cada PR o cambio de prompt.
  • [ ] False Positives Check: La rúbrica de evaluación ha sido probada inyectando respuestas intencionalmente malas para verificar que el evaluador falla correctamente.

2. Security & Boundaries

  • [ ] Prompt Injection Defenses: El input del usuario está acotado (Boundaries) y no se confía ciegamente en él.
  • [ ] PII Masking: Existe un filtro determinista (Regex/Spacy) antes de que el texto viaje al proveedor del LLM.
  • [ ] Tool Sandboxing: Las herramientas que el agente puede ejecutar tienen permisos de infraestructura limitados (Principio de menor privilegio).

3. Reliability & Fallbacks

  • [ ] Multi-Provider Routing: El sistema puede enrutar automáticamente a un modelo de respaldo si la API principal se cae.
  • [ ] Graceful Degradation: Si el LLM falla, el usuario recibe un flujo determinista (ej. botones estándar) en lugar de un error genérico.

4. Observability, Cost & Latency

  • [ ] Token Tracking: Cada inferencia taggea el costo y el uso de tokens por usuario/tenant.
  • [ ] Traceability: Se registran los pasos internos del agente (qué tools llamó, qué prompts usó) para depurar alucinaciones.
  • [ ] Latency Budgets: Las tareas triviales usan modelos rápidos (pequeños), reservando los modelos grandes para tareas complejas.

5. Human Review (HitL)

  • [ ] Mutation Risk Approval: Ninguna herramienta de escritura/borrado se ejecuta sin aprobación asíncrona de un humano (Human-in-the-Loop).
