Tool Definition Schema

JSON Schema Pattern para Llamada de Herramientas

Para que un LLM (OpenAI, Anthropic, Gemini, etc.) pueda utilizar herramientas, debes enviarle una definición estricta de qué hace la herramienta y qué parámetros acepta. El estándar de facto en la industria para esto es el JSON Schema.

// get_current_weather.json

{{ '{' }} "name": "get_current_weather", "description": "Obtiene el clima actual para una ubicación dada.", "parameters": {{ '{' }} "type": "object", "properties": {{ '{' }} "location": {{ '{' }} "type": "string", "description": "La ciudad y el estado, ej. San Francisco, CA" {{ '}' }}, "unit": {{ '{' }} "type": "string", "enum": ["celsius", "fahrenheit"], "description": "La unidad de temperatura a devolver" {{ '}' }} {{ '}' }}, "required": ["location"] {{ '}' }} {{ '}' }}
Metadata

name & description

El LLM usa el `name` para llamar a la función, pero usa la `description` para decidir cuándo llamarla. Escribir buenas descripciones es clave para el éxito del agente.

Data Types

parameters & properties

Define los tipos de datos (string, integer, boolean). Puedes usar `enum` para forzar al modelo a elegir de una lista cerrada de opciones, previniendo alucinaciones.
